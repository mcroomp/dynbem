rotor_profile: Aerodynamic model profiler for VPM (direct/BH), Pitt-Peters, Øye, and BEM

USAGE:
  rotor_profile [MODELS] [OPTIONS]

MODELS (comma-separated, case-insensitive):
  vpm-direct     - VPM direct O(N²) velocity evaluation
  vpm-bh         - VPM Barnes-Hut O(N log N) tree (theta=0.5)
  pitt-peters    - Global 3-state Pitt-Peters inflow model
  oye            - Per-annulus 2-stage Øye filter model
  bem            - Quasi-static BEM with Brent solver
  all            - All models (default if none specified)

  Examples:
    rotor_profile vpm-direct,vpm-bh
    rotor_profile all
    rotor_profile pitt-peters

PARTICLE COUNTS (VPM only):
  Default: 500, 2000, 5000, 10000, 20000
  (Other models ignore this parameter)

OPTIONS:
  --max-particles <N>
    Cap the VPM max_particles per config (default: 20000).
    Useful for memory-constrained profiling.

  --duration <secs>
    Wall-clock time per model/config (default: 10.0 s).
    Longer durations reduce measurement noise.

  --output <format>
    Output format: csv, md (markdown), or text (default: text).
    Use 'csv' to pipe into spreadsheet or Python pandas.

  --seq
    Force single-threaded (no Rayon parallelism).
    Useful for fair comparison or when --features parallel is enabled.

  --help, -h
    Show this message and exit.

EXAMPLES:
  # Quick profile of all models (10s each):
  rotor_profile all --duration 10

  # VPM direct vs tree at default particle counts (30s each):
  rotor_profile vpm-direct,vpm-bh --duration 30

  # BEM family models, output as CSV:
  rotor_profile pitt-peters,oye,bem --output csv > bem_family.csv

  # VPM at modest particle counts (memory/time constrained):
  rotor_profile vpm-bh --max-particles 5000 --duration 20

OUTPUT:
  All timing is in milliseconds per forward-flight step (18 steps/rev for VPM,
  one call for BEM-family models). Results are printed to stdout; diagnostic
  messages go to stderr.

BUILD:
  cargo build --release -p dynbem_rs [--features parallel]
  ./target/release/rotor_profile [args...]
